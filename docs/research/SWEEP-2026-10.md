  "-Project=<worktree>\apps\vr\Game\MageArenaVR.uproject" "-OutputDir=<worktree>\apps\vr\Game\Saved\ClangDb" `

Exit 0, 4 s wall (UBT: `Total execution time: 2.55 seconds`). The database has 1 entry, KernelData.cpp. It is
`clang-cl.exe` from Visual Studio's LLVM 19, with `@KernelData.cpp.obj.rsp`. Three things went wrong on the way,
and each one is worth knowing for the next sweep:

1. `UnrealBuildTool.exe` called directly exits 150 (`You must install or update .NET`: it needs the .NET 10
   runtime, and the machine has 3.1 to 9.0). `Build.bat` selects the engine's bundled .NET 10 SDK and passes every
   argument through to UBT, so the mode runs through `Build.bat`.
2. **UE 5.8 `GenerateClangDatabase` writes its clang-cl `.rsp` files into the normal build's intermediate folder**
   (`Intermediate/Build/Win64/x64/UnrealEditor/Development/MageArenaVR/`). They replace the MSVC response files,
   and the old shared one is left as `MageArenaVR.Shared.rsp.old`. With a cached makefile, the next MSVC build
   would read clang flags. Before the next build I deleted this worktree's
   `Intermediate/Build/Win64/x64/MageArenaVREditor/Development/Makefile.bin`. UBT then printed
   `Creating makefile for MageArenaVREditor (no existing makefile)`, rewrote the response files with MSVC flags and
   recompiled 66 actions (exit 0, 50 s).
3. For the same reason, the database would point at files the next build overwrites. Its three inputs
   (`KernelData.cpp.obj.rsp`, `MageArenaVR.Shared.rsp`, `Definitions.h`) were copied to
   `apps/vr/Game/Saved/ClangDb/rsp/`, and the database and the `.rsp` were repointed there. The flags are unchanged;
   only paths moved. UBT's original database is kept beside it as `compile_commands.ubt.json`. Nothing in
   `Saved/` is committed.

### 1.2 The clang-tidy command

```
"C:/Program Files/LLVM/bin/clang-tidy.exe" -p apps/vr/Game/Saved/ClangDb \
  --config='{Checks: "-*,readability-function-size,readability-function-cognitive-complexity,misc-unused-*,bugprone-*,performance-*", CheckOptions: {readability-function-size.LineThreshold: 100, readability-function-cognitive-complexity.DescribeBasicIncrements: false}}' \
  --header-filter='KernelData\.h$' \
  "--extra-arg=-resource-dir=C:/Program Files/LLVM/lib/clang/22" --extra-arg=-Wno-unused-command-line-argument \
  apps/vr/Game/Source/MageArenaVR/Kernel/KernelData.cpp
```

Run from the worktree root, in Git Bash. The two `--extra-arg`s are needed:

- The database's clang-cl is LLVM 19, and its response file passes `-resource-dir` to clang 19's builtin headers.
  clang-tidy 22 cannot parse those headers. The first run exited 1 with `2259 warnings and 21 errors generated`,
  every error in `lib/clang/19/include/mmintrin.h` (`use of undeclared identifier '__builtin_ia32_vec_init_v2si'`).
  Pointing `-resource-dir` at clang 22's own headers fixes it.
- clang-tidy only parses, so `/c` in the response file goes unused. The response file's `/W4 -Werror` then turns
  the "argument unused during compilation" warning into an error.

**Exit code 1 before, 0 after.** The 1 is not a tool failure. The parse completed: findings are reported up to line
1741 of 1775. The 3 errors are real `-Wrange-loop-construct` diagnostics on the target code, made errors by the
`-Werror` from UBT's own response file (finding 5). Once those were fixed, the same command exits 0.

### What the scan cannot see

- **GNU mode.** clang-cl compiles with `-fms-compatibility` and `/permissive-`. It accepts MSVC extensions that the
  NDK's clang rejects (a dependent name without `typename`, unqualified lookup into a dependent base, MSVC preprocessor
  behaviour). The engine artefact shows the reverse: `TRACE_PRIVATE_EXPAND` in `TraceLog/Public/Trace/Trace.h:20` is
  written for MSVC's preprocessor. Under clang-cl it expands to a comma expression, which gives 21 `-Wunused-value`
  errors per file in the PCH variant. The engine builds for Android with `-Wall -Werror`, so that expansion does not happen in GNU
  mode. These errors are counted as engine, not as findings.
- **Engine headers' Android branches**: `PLATFORM_ANDROID` code, Android `int`/`long` widths (`long` is 64-bit on
  arm64 Android and 32-bit on Win64, which changes overload resolution), the Android `FPlatform*` types. The module
  itself has no such block.
- **The compiler.** The scan is clang 19.1.5. Android uses the NDK's clang, NDK r27c to r29 per `Android_SDK.json`
  (r28.2's is clang 19.0.1). A diagnostic added or changed between those versions is not seen.
- **Game target and configuration.** The scan is the editor target's Development response file, with the Engine shared
  PCH added by hand. An Android Shipping build compiles out the 26 `WITH_DEV_AUTOMATION_TESTS` files, and switches
  `-Wunused-value` off (`CppCompileWarnings.cs:635`).
- **Anything after the front end**: link errors, the Android `.so`, UBT's Android-only checks, packaging.
- **v2/slice**: not compiled; see lane A's list.
