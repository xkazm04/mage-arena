## K2 - Canon conformance with the TV pin (M2, M3, M4)

- **Measure:** two numbers. (a) the exit code of `node apps/vr/tools/check-pin.mjs`. (b) how many of the committed
  vectors in `apps/vr/data/conformance/` the TS oracle regenerates byte-identical, run outside the repo. A third check,
  `check-pin.mjs --source <TV clone>`, confirms the pinned bytes against the TV repo itself.
- **Method (a script):** `generate.mjs` writes into `<vrRoot>/data/conformance` and `<vrRoot>/.cache`, so it runs on a
  scratch copy and never inside the checkout:

  ```sh
  S="$TEMP/kpi-<run>"; mkdir -p "$S/scratch/apps/vr" "$S/tsx"
  GIT_LFS_SKIP_SMUDGE=1 git clone -q https://github.com/xkazm04/mage-arena-pc "$S/tv"   # the TV canon (REPO-LAYOUT's mage-arena-tv)
  (cd "$S/tsx" && npm init -y && npm install tsx@4.19.2)                               # outside the repo
  cp -r apps/vr/tools apps/vr/data "$S/scratch/apps/vr/"
  rm -f "$S/scratch/apps/vr/data/conformance/"*                                          # so every compared file is fresh
  (cd "$S/scratch/apps/vr" && MAGE_ARENA_ARENA="$S/tv" TSX_CLI="$S/tsx/node_modules/tsx/dist/cli.mjs" \
     node tools/conformance/generate.mjs)
  for f in apps/vr/data/conformance/*; do cmp -s "$f" "$S/scratch/apps/vr/data/conformance/$(basename "$f")" || echo "DIFF $f"; done
  node apps/vr/tools/check-pin.mjs && node apps/vr/tools/check-pin.mjs --source "$S/tv"
  git status --short    # must print nothing
  ```

- **Target:** check-pin exit 0, `source match for 9 files`, and 45/45 identical, at every reading. Any diff is a canon
  break and is raised before any card lands.
- **First reading, 2026-10-20 (measured, Lynx, in `%TEMP%\kpi-d4fde2ae`):** **pass.**
  - `generate.mjs` exited 0 and wrote 45 vectors into the emptied scratch folder. All 45 are `cmp`-identical to the
    tracked ones, 0 differ.
  - `check-pin.mjs`: `pin OK: 9 files @ baeac66`, exit 0.
  - `--source`: `pin OK, source match for 9 files`, exit 0.
  - `git status --short` printed nothing.
  - This agrees with the 2026-10-20 reading in `docs/research/STATE-EVAL-2026-10-20.md` section 5.
- **Limit:** this proves that the TS oracle reproduces the committed vectors. That the C++ kernel matches them is
  `MageArena.Kernel.Conformance.*`, which is **not measurable on Lynx**. The Wolf step is the `MageArena` suite after
  `apps/vr/tools/build.ps1`, counting the 45 conformance tests; the last record is 45/45 at `b7f1009` (read).
